# Evidencia de CA-RF03-06

## Alcance verificado

CA-RF03-06 exige una respuesta `400` para valores conocidos inválidos de
`ordering`, `category` o `license`, sin construir una ordenación con texto no
reconocido. También exige que ese error tenga precedencia sobre una página
inválida.

## Regresión observada

```bash
.venv/bin/python -m pytest -q \
  apps/catalog/tests/test_views.py::test_catalog_renders_category_and_license_selects_with_active_options_and_recognized_value \
  apps/catalog/tests/test_views.py::test_catalog_shows_message_and_keeps_all_recognized_controls_visible_when_query_has_no_matches \
  apps/catalog/tests/test_views.py::test_catalog_returns_400_for_a_normalized_search_query_longer_than_100_characters \
  apps/catalog/tests/test_views.py::test_catalog_returns_400_for_an_unrecognized_ordering_value \
  apps/catalog/tests/test_views.py::test_catalog_returns_400_for_an_unrecognized_category_slug \
  apps/catalog/tests/test_views.py::test_catalog_returns_400_for_an_unrecognized_license_slug \
  apps/catalog/tests/test_views.py::test_catalog_returns_400_instead_of_404_when_an_invalid_category_and_an_invalid_page_are_combined
```

Resultado observado: `7 passed in 0.49s`.

Las cinco últimas pruebas de la orden verifican, respectivamente, el límite
normalizado de `q`, la ordenación no permitida, los dos `slug` inexistentes y la
precedencia de `400` sobre `404`. No se creó un estado Red en este cierre porque
no se modificó comportamiento de producción.
