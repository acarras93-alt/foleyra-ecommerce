# Evidencia de CA-RF01-01

## Alcance verificado

CA-RF01-01 verifica que un visitante puede abrir `/catalog/` y ver un producto
cuando el producto, su categoría y al menos una oferta de licencia están activos.

La comprobación usa datos aislados creados por la prueba; no depende de la
fixture de demostración definida para otro incremento.

## Ciclo test-first observado

### RED

Con PostgreSQL disponible, se ejecutó:

```bash
.venv/bin/python -m pytest apps/catalog/tests/test_views.py -q
```

La prueba falló con `assert 404 == 200` al solicitar `GET /catalog/`. El fallo
confirmó que no existía todavía la interfaz HTTP del catálogo; las siete
pruebas preexistentes pasaban.

### GREEN

Tras integrar el selector de productos disponibles con la interfaz web mínima,
se ejecutó:

```bash
.venv/bin/python -m pytest apps/catalog/tests/test_views.py -q
```

Resultado observado: `1 passed`.

## Cobertura de CA-RF01-02

CA-RF01-02 verifica que un producto inactivo no aparece al consultar
`/catalog/`, aunque su categoría y oferta de licencia estén activas.

Se añadió una prueba HTTP aislada que crea ese conjunto de datos, comprueba la
respuesta `200` y confirma la ausencia del nombre del producto. La prueba pasó
en su primera ejecución porque `get_available_products()` ya filtraba
`Product.is_active=True` desde CA-RF01-01.

Este resultado es cobertura añadida de comportamiento preexistente; no hubo un
ciclo RED-GREEN nuevo ni se modificó código de producción.

fixture de demostración ni los demás criterios de RF-01.
